Device Replacement & Subscription Handling Procedure

📅 Version 01 📂 System: Cypherdesk 👤 Audience: Technical Support / Installation Team

This procedure defines how to handle device replacements where the client supplies a different device than what was originally installed, and how to correctly manage the associated subscription in Cypherdesk. Following the correct scenario below prevents billing errors and incorrect product/subscription records on the asset.

Key principle: A device swap (VTS ↔ FMS) with the same subscription type is treated as a repair/replacement job. A change in subscription type (e.g. FMS → VTS) is always treated as a new installation.

1. Scenario 1: Client Provides a Different Device (Swap Between VTS & FMS)

This scenario applies when the installed device is DOA (Dead on Arrival) and the client provides a replacement device of a different type than what was originally quoted — but the subscription itself is not changing.

Case A — VTS Device DOA → Client Provides FMS Device

StepAction
1Create a Billable Job Card
2Add the following under Features: De-installation, Re-installation
3Update Device Type, Device Serial Number & SIM Details
4When Cypherdesk prompts about the serial number change, enter: “Client provided a previously de-installed FMS device. Subscription will remain as VTS.”
Important: Even though the replacement hardware is an FMS device, the product and subscription remain as VTS.

Case B — FMS Device DOA → Client Provides VTS Device

StepAction
1Create a Billable Job Card
2Add the following under Features: De-installation, Re-installation
3Update Device Type, Device Serial Number & SIM Details
4When Cypherdesk prompts about the serial number change, enter: “Client provided a previously de-installed VTS device. Subscription will remain as FMS.”
Important: Even though the replacement hardware is a VTS device, the product and subscription remain as FMS.

2. Scenario 2: Client Downgrades from FMS to VTS (FMS Device DOA)

This scenario applies when the client is moving to a different subscription type — not just swapping hardware.

StepAction
1Suspend the FMS Device and Subscription in Cypherdesk
2Create a New VTS Installation Job Card with a VTS Subscription for the existing vehicle
3This generates a new product on the asset with a VTS subscription
Key Point: This is treated as a new installation, not a swap, because the subscription type is changing.

3. Summary

ScenarioAction
Replacement with stock provided by client (same subscription)Billable Job Card · De-installation & Re-installation added · Device info updated · Subscription remains unchanged
Replacement with different product type (e.g. FMS → VTS)Suspend old subscription · New installation Job Card created · New subscription applied
Acknowledgment: All technical support and installation staff are required to read, understand, and follow this procedure. A signed acknowledgment form is kept on file with the Technical Manager.
